## 三、FLOOR 归因重做（F2.1j）—— 推翻 F2.6
F2.6 用估算的 200GB/s 得出"240KB=1.23us ≈ floor差1.18us"。
按实测 109GB/s 重算 = 2.25us, 不吻合(差1.9倍)。原论证不成立。

新归因(基于 msprof 分项):
  Case1(BD=1)  总7.82  aiv 7.173  scalar 3.319(46%) mte2 1.721 vec 0.554
  Case5(BD=8)  总15.14 aiv 13.974 scalar 5.473(39%) mte2 3.611 vec 2.231

三条洞察:
1. Case1 mte2=1.721us 但数据仅 288B -> 0.17GB/s 荒谬
   => 这是 DMA 启动延迟, 不是带宽传输
2. Case1 aiv_time 是 Case5 的一半, 但数据量只有 1/170
   => Case1 完全由固定开销主导, 与数据量无关
3. 两 case 的 scalar 占比都最高(46%/39%), 与 shape 无关
   => 这才是真正的共性瓶颈

修正后的 floor 模型:
  floor ≈ 固定部分(DMA启动1.7us + 标量3.3us) + 数据相关部分(mte2+vec)

优化含义:
- 削 scalar (最大项, 与 shape 无关) -> 全 case 有效
- 削 mte2 启动延迟 -> Case1 收益最大
- 换归约原语只影响 vec(8~16%, 第三位) -> ROI 最低
